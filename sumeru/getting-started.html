06 / Start building

Two ways in.

The same system, read from two directions: the commands that get it running, and the business flow it gives you once it is.

You need Go 1.26+ and PostgreSQL. Nothing else: no Node, no Docker, no message broker. Every command below runs from your workspace module, sumeru_custom_addons.

  1. 1

    Create the database and the config

    $ psql -U postgres -c "CREATE DATABASE sumeru;"

$ cd sumeru_custom_addons
$ cp sumeru.conf.example sumeru.conf
# edit db_host / db_user / db_password / db_name / http_port

    Paths inside the INI resolve against the file itself, not your shell. The addons_path key is what decides which addons exist at all.

  2. 2

    Point the workspace at the other two modules

    $ make replace-sumeru        SUMERU_ROOT=../sumeru
$ make replace-sumeru-addons ADDONS_ROOT=../sumeru_addons
$ make generate

    make generate rewrites addonimports/zimports.go, the blank imports that link every discovered addon into the binary. Run it whenever you add an addon.

  3. 3

    First boot: the setup wizard

    $ make run

Database is not initialized. Starting in SETUP MODE.
Visit http://localhost:9090/setup to initialize the system.

    There is no default admin account. The wizard at /setup creates your company and the first user; the email you give it becomes the login.

  4. 4

    Install the business addons

    $ go run . -- -c sumeru.conf \
    -i contacts,product,crm,sale,sale_crm,account,purchase,hr \
    --stop-after-init

    Install order matters and follows depends. -i all is rejected on purpose . You name what you want.

  5. 5

    Run it

    $ make run
Server starting on :9090...

# open http://localhost:9090/  →  /web/home

The inner loop for a new addon

# scaffold: manifest, init.go, models, views, menus, security
$ go run ../sumeru/cmd/sumeru-bp -name my_module -out ./addons

# link it into the binary, then install it once
$ make generate
$ go run . -- -c sumeru.conf -i my_module --stop-after-init

# after editing any XML or the manifest's data list, reload it
$ go run . -- -c sumeru.conf -u my_module --stop-after-init
$ make run

Go code changes need a rebuild. That is what make run does. XML changes need -u, because views, menus and access rules live in the database once installed.

Server flags

Flag What it does Note
-c <path> Config file to read Defaults to sumeru.conf
-i <mods> Install addons, comma-separated all is rejected
-u <mods> Reload addon data and schema -u all is allowed
-d, --database Override the database name Beats the config file
-p, --http-port Override the listen port Beats the config file
--stop-after-init Exit after install/update Only acts with -i or -u

No commands here. This is what the system does once it is running, what you can change yourself, and what still needs an engineer.

01

You switch apps on

The Apps screen lists every available module. Installing one brings its own menus, screens and permission groups. Install only what you use.

02

Roles decide what people see

Users belong to groups, and groups carry both menu visibility and record access. A salesperson sees their own orders; a manager sees all of them.

03

One database, several companies

A group of companies runs on a single system with a switcher in the top bar. Records follow the company they were created in.

The flow that works today

Each arrow is automatic. The system reacts to a status change rather than asking someone to re-key the same figures into the next screen.

  1. LeadCRM pipeline
  2. Wonstage marked won
  3. Quotationdraft sales order
  4. Sales orderconfirmed
  5. Invoicedraft, then posted
  6. Journal entriesbalanced, double-entry

Purchasing runs the same way: confirm a purchase order and a vendor bill is drafted against it.

What is genuinely missing

  • Taxes: no tax engine on any document.
  • Payments: invoices carry a payment status, but nothing registers a payment or reconciles a bank statement.
  • Order totals: sales order amounts are stored, not yet computed from their lines.
  • Inventory: no stock, warehouses or manufacturing at all.
  • Reports: no printable documents, no financial statements.
  • Tests: the business addons have no automated test suite.
Heads up. Sumeru is pre-alpha. Do not run your business on it yet.
