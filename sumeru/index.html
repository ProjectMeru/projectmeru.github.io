Open source · Pre-alpha · Dual licensed

Addons included.One kernel.

Sumeru is an open-source modular ERP framework in Go. Business functions are addons: contacts, products, CRM, sales, invoicing. Declare models with sdk.Model, wire XML views, and run day-to-day work in a SWC workspace with search, filters, and saved searches across list, form, kanban, graph, pivot, and more.

01 / Foundation

One design.
Every addon.

The ORM, XML views, access rights, event bus and JSON-RPC API ship as one kernel and share one addon contract. Declare a model once: it becomes a table, a form, and an API resource.

account_journal.go 
package models

import "sumeru/core/sdk"

type AccountJournal struct {
    sdk.Model `sumeru:"model=account.journal"`

    Name   sdk.String  `sumeru:"required,string=Name"`
    Code   sdk.String  `sumeru:"required,string=Code"`
    Active sdk.Boolean `sumeru:"string=Active,default=true"`
}
Run make generate after adding a struct so models/zmodels.go registers it. Schema syncs on install.

Models register from generated zmodels.go, not hand-written init() blocks.

List, form, and kanban views plus sys.action.window records load on install. The arch JSON pipeline feeds the SWC client.

Groups with inheritance, per-model rights from CSV, and row-level record rules.

Addons subscribe without importing each other: uninstall Sales and Invoicing keeps working.

API keys from your user record; access rights apply exactly as they do in the UI.

Recurring work needs no Redis, no Celery, no sidecar workers.

04 / Sumeru systems

One idiom,
every subsystem.

Dependency-free addon integration, a SWC workspace client, and multi-company on a single database. All following the same shape.

01 · Addons

A folder is a product surface

Manifest, models, views, menus, security. The kernel discovers it, topologically orders depends, syncs schema and loads data files.

02 · UI

SWC workspace client

TypeScript sources in core/swc/; bundles built locally via make setup. Plain CSS shell for chrome and login — no runtime npm on the server.

03 · Events

Integrate without importing

Invoicing reacts to a confirmed sales order it has no compile-time knowledge of. Registry lookups keep optional counterparts optional.

04 · Companies

One database, many companies

Switcher in the top bar, per-user company access, record rules scoped to the active company. Not multi-tenant. Separate customers need separate deployments.
