    Template-driven PDF reports

    Sumeru ships tabular CSV/PDF/XLSX export from workspace views today (core/report/export_csv.go, export_pdf.go, export_xlsx.go). This guide describes the next step: layout PDFs for invoices, orders, and other printable documents — without a server-side XML template engine.

    Recommended architecture (P0 spike)

    mermaid
    mermaid
    flowchart LR
  Action["ir.actions.report or object action"]
  GoService["Go report service"]
  Template["Go text/template or HTML subset"]
  GPDF["gpdf document builder"]
  PDF["application/pdf"]
  Action --> GoService --> Template --> GPDF --> PDF
    1. Register printable actions in addon Go code (RegisterObjectAction or a future report.RegisterTemplate).
    2. Build a report.TemplatePDFInput (title, subtitle, sections, optional table) from ORM records in Go.
    3. Render with report.ExportTemplatePDF (spike in core/report/export_template_pdf.go).
    4. Serve via GET /web/report/template-pdf?title=…&subtitle=… (session required; spike — builds a demo layout from query params until action registration exists).

    Spike API (implemented)

    go
    go
    pdfBytes, err := report.ExportTemplatePDF(report.TemplatePDFInput{
    Title:    "Sales Order SO-001",
    Subtitle: "Acme Corp",
    Sections: []report.TemplatePDFSection{
        {Heading: "Terms", Body: "Net 30 days"},
    },
    TableHead: []string{"Product", "Qty", "Unit price"},
    TableRows: [][]string{{"Widget", "3", "10.00"}},
    PageSize:  report.PageSizeA4,
})

    Plain-text preview for tests: report.RenderTemplatePDFText.

    XML / manifest hook (future)

    Possible v2 declaration on views or actions:

    xml
    xml
    <report template="sale.report_order" download="pdf" layout="document"/>

    Parser would store layout=document in capabilities; handler would resolve a Go-registered template by name. Not wired yet — addon authors should call ExportTemplatePDF from object actions until registration exists.

    HTML → PDF path (deferred)

    Reference ERP stacks often render HTML templates to PDF (wkhtmltopdf or headless Chrome). Sumeru avoids that dependency in v1:

    • Pros of gpdf + Go structs: No browser binary, predictable layout, same stack as tabular PDF.
    • When to revisit: If addon authors need pixel-perfect HTML/CSS invoices, add an optional html/template → gpdf bridge or external renderer behind a feature flag.

    Relation to view

    View XML remains for workspace export. Template PDFs are per-record documents triggered by form buttons or server actions — mirror the separation in mature ERP products between list export and printable reports.
