    Reference ERP patterns in Sumeru

    Use this cookbook when porting addons from erp_0 (the reference tree under sumeru_erp/erp_0) or other Python/XML ERP modules into Sumeru. Sumeru is Go-centric: business logic belongs in Go services; views stay XML; UI extensions use SWC.

    Views and inheritance

    Reference: extension view with xpath on a group inside a form sheet.

    xml
    xml
    <xpath expr="//group[@string='Order Lines']" position="inside">
    <field name="custom_note"/>
</xpath>

    Sumeru: Same xpath syntax in inherit arch (inherit_id / inherit= on ). Supported positions: after, before, inside, replace, attributes. Targets include field, button, group, sheet, header, notebook, page, and more.

    Reference: primary view mode="primary".

    Sumeru: Define a full arch or use inherit= on model fields; primary/extension modes are not separate flags — use a new view id or inherit arch.

    Reporting

    Reference: list export CSV/XLSX and printable invoice PDF.

    Sumeru list export:

    xml
    xml
    <view type="list" model="sale.order">
    <report download="csv,pdf,xlsx" pdf_sizes="a4,letter"/>
    <field name="name"/>
</view>

    Sumeru document PDF: build report.TemplatePDFInput in a Go object action handler (see template-reports guide). Not driven by server-side XML templates.

    Assets and theming

    Reference manifest:

    python
    python
    'assets': {
    'web.assets_backend': ['my_module/static/src/css/custom.scss'],
}

    Sumeru manifest.json:

    json
    json
    {
  "assets": [
    "static/css/custom.css",
    "static/js/widget.js"
  ]
}

    CSS entries are injected into the shell stylesheet list when the module is installed. For theme tokens, prefer --sum-* overrides in static/css/theme-overrides.css.

    Module layout

    Follow MODULE_STANDARD.txt: one XML file per model view set, manifest.json, models/*.go, optional static/.

    What not to port verbatim

    • Python ORM decorators → rewrite as Go registrations
    • Server template loops in view arch → modifiers, Sum templates, or Go
    • safe_eval domains in XML → Go domains or static XML domains
    • Asset bundle keys (web.assets_backend) → flat assets array paths
