    Web Icons

    Sumeru uses an SVG sprite system for menu icons. This approach is highly performant as it requires only a single HTTP request, is easily cached by the browser, and avoids the overhead of a heavy Javascript icon library.

    How it works

    When you define a in an XML file, the web_icon attribute determines which icon is displayed in the sidebar or top bar:

    xml
    xml
    <menuitem id="menu_my_app" name="My App" web_icon="package"/>

    The system maps the web_icon value (e.g., package) to a symbol ID in the global SVG sprite file:

    core/engine/assets/img/menu-icons.svg#i-package

    Adding New Icons

    To add a new icon to the system:

    1. Find the Icon: Go to Lucide.dev and find the icon you need.
    2. Get the SVG Path: Copy the SVG paths (, , etc.) from the Lucide site.
    3. Update the Sprite: Open sumeru/core/engine/assets/img/menu-icons.svg.
    4. Add a : Create a new symbol at the end of the section:

    ```xml

    ```

    1. Use it: You can now use web_icon="your-icon-name" in any menu definition.

    [!TIP]

    Always use i- prefix for the symbol ID in the SVG file, but omit it when referencing the icon in the web_icon attribute.

    Manifest assets

    Addons can declare extra CSS or JS in manifest.json:

    json
    json
    {
  "assets": [
    "static/css/custom.css",
    "static/js/widget.js"
  ]
}

    When the module is installed, each file is served at /static/addon-asset//. CSS paths are appended to the shell stylesheet list (same lifecycle as static/css/theme-overrides.css). JS assets are served but not auto-injected — load them from Sum templates or SWC entry modules.

    See Reference ERP patterns for porting asset bundles from other ERP codebases.
