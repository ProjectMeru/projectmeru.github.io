Configuration

How the INI config and CLI flags control database, port, addon discovery and install.

Pre-alpha. Sumeru has no tagged release and no upgrade path. Fine for local eval and addon work. Do not run production on it.

The config file

Copy the example and edit it in the workspace:

Terminal
shell 
$cp sumeru.conf.example sumeru.conf

Paths inside the INI resolve against the config file's directory, not your current working directory.

Common keys

KeyPurpose
db_host, db_port, db_user, db_password, db_namePostgreSQL connection
http_portListen port (often 8080)
addons_pathComma-separated directories to scan for addon manifests

Note. Exact key names follow sumeru.conf.example in your checkout. Treat that file as the source of truth if a key differs.

CLI overrides

FlagWhat it doesNote
-c <path>Config file to readDefaults to sumeru.conf
-d, --databaseOverride database nameBeats the config file
-p, --http-portOverride listen portBeats the config file
-i <mods>Install addons, comma-separatedall is rejected
-u <mods>Reload addon data and schema-u all is allowed
--stop-after-initExit after install/updateOnly with -i or -u

addons_path

This key decides which addons exist at all. Point it at the standard addons tree and your workspace addons directory so both are discoverable.

Next step

Continue with First boot to initialise the database and install business addons.

What not to do

  • Do not resolve relative paths from your shell cwd; they resolve from the config file.
  • Do not use -i all; name the addons you want.
