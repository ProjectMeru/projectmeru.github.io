    How to run from `sumeru_custom_addons`

    Goal: keep sumeru/ and sumeru_addons/ read-only while you develop client modules under addons/.

    Summary

    The sibling directory sumeru_custom_addons/ is a Go workspace with:

    • Its own go.mod and replace directives to core and standard apps
    • Generated addonimports/zimports.go (blank imports for every addon on addons_path)
    • Local sumeru.conf (gitignored)
    • Makefile targets that delegate SWC builds to ../sumeru

    Pre-shipped reference: addons/my_module — kitchen-sink demo (all view types and widgets). It is not recreated by make new MODULE=my_module; clone the repo to get it.

    Quick start

    1. Copy sumeru.conf.example → sumeru.conf and set database + addons_path (typically ../sumeru/addons, ../sumeru_addons, ./addons).
    1. From sumeru_custom_addons/:
    make setup
make install MODULES=my_module   # optional: explore kitchen-sink demo
make run
    TargetEffect
    make setupgo.mod replaces, make generate, SWC assets, create sumeru.conf if missing
    make run / make devgenerate → assets → HTTP server
    make generateRefresh addonimports/zimports.go, each addon's zmodels.go / zrefs.go, overwrite init.go
    make new MODULE=xScaffold minimal module under addons/, then generate
    make install MODULES=x-i then exit
    make update MODULES=x-u then exit
    make buildgenerate + assets + bin/sumeru-erp
    make checkswc-check + go test ./...
    make assets / make swcDelegate to ../sumeru for client bundles
    1. After adding a model struct or changing depends in a manifest, run make generate again. Do not hand-edit generated files.

    Client assets

    Browser bundles are built in ../sumeru/core/engine/assets/ and are not committed to git. make setup and make run build them automatically. Requires Node.js on the machine running those commands.
